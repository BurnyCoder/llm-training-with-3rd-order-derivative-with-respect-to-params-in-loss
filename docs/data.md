# Corpus preparation

The public entry point `thirdloss.data.prepare(stage, root)` creates a self-contained `stories` or `abstracts` stage directory under the selected data root. A repeat call verifies its checksums and recovers damaged output. The original source cache lives alongside the prepared stages. The Hub client uses an immutable revision. A public HTTPS fallback checks the same upstream object identity and size before accepting the bytes. [Hub download API](https://huggingface.co/docs/huggingface_hub/package_reference/file_download)

## Cohorts

| Stage | Source and assignment |
|---|---|
| Stories | Take the first 160,000 rows of the source training split in physical parquet row order. Assign a story to development when the integer encoded by the first 16 hex digits of its normalized SHA-256 hash is divisible by 50. Use all rows from the official validation parquet as candidate test documents. Source row IDs remain stable across re-runs. [Pinned input files](https://huggingface.co/datasets/roneneldan/TinyStories/tree/f54c09fd23315a6f9c86f9dc80f725de7d8f9c64/data) · [Arrow streaming reader](https://arrow.apache.org/docs/python/generated/pyarrow.parquet.ParquetFile.html) |
| Abstracts | Scan both compressed JSONL shards. Use the source `created` timestamp to select first submissions in January through April 2024 for training, May for development and June for testing. Group versions using the base arXiv identifier and retain the first source record per ID. Log how often the identifier month differs from the creation month. The corpus stores the abstract available at collection time, which can include revisions after submission. [Pinned abstracts](https://huggingface.co/datasets/common-pile/arxiv_abstracts_filtered/tree/dc1ceab4755eb037ec61e49cf1350dab7ceee6e7) · [arXiv identifier scheme](https://info.arxiv.org/help/arxiv_identifier.html) · [Upstream first-version timestamp example](https://arxiv.org/abs/0704.0001) |

## Overlap audit

Hash Unicode NFKC, case-folded, whitespace-collapsed text. Retain the earliest exact copy within each split with priority given to test, then development, then training. Train the tokenizer on the original retained text after trimming outer whitespace. For cross-split near copies, form sets of five consecutive Unicode word tokens. Short documents form one shingle. Punctuation-only documents retain a normalized whole-text key.

The audit excludes any lower-priority document that reaches Jaccard similarity 4/5 against a retained higher-priority document. To identify candidates, order shingles by their reference-split document frequency, then lexically. With n shingles, index the first floor(n/5)+1. Every pair meeting the cutoff must share a prefix term under this common ordering. Verify candidates by exact set intersection. Evaluation references with the earliest source index break a match tie. Every exclusion has an auditable reason and matched ID. This procedure detects all cross-split copies meeting the stated whole-document shingle criterion. Paraphrases, snippets copied inside a longer document, and lower-similarity boilerplate can survive. Near matches within a single split can also survive and affect its diversity. [Xiao et al., §2.2](https://archives.iw3c2.org/www2008/papers/pdf/p131-xiaoA.pdf)

## Token and evidence files

The independent post-hoc check found exact passages shared by retained TinyStories training and test documents. Its per-seed counts intersect the matches with the complete input-and-target windows actually selected during training. The released aggregate test NLL cannot isolate the affected stories. [Exposure by seed and matching criteria](../reports/reviews/independent-scientific-audit.md) · [Exact substring deduplication](https://aclanthology.org/2022.acl-long.577/)

- Stories use byte-level BPE with a complete byte alphabet, one end-of-text symbol, 4,096 entries, and all retained training documents. Abstracts reuse the exact tokenizer bytes of the base model. The manifest separates the largest usable tokenizer ID plus one from Pythia’s padded output-head width. [BPE trainer](https://huggingface.co/docs/tokenizers/en/api/trainers) · [Pinned base checkpoint](https://huggingface.co/EleutherAI/pythia-410m/tree/9879c9b5f8bea9051dcb0e68dff21493d67e9d4f)
- Each split is a contiguous little-endian uint16 file ordered by source row, with one appended EOS per document and no injected BOS. The model can see previous documents in a packed window across EOS boundaries. Context and next-target shifting belong to the training/evaluation code. An example file opens with `numpy.memmap(stage_dir / "train.bin", dtype="<u2", mode="r")`.
- `documents.jsonl` gives each retained document’s source ID, normalized content hash, starting token, and length including EOS. Abstracts additionally include the submitted timestamp. `rejections.jsonl` lists rejected document IDs and reasons. These two files contain metadata rather than copies of source documents.
- `manifest.json` records split counts, audit counts, source revisions, source and output SHA-256 hashes, encoding settings and vocabulary dimensions. The stage-local lock serializes preparation. A temporary build promotes verified outputs atomically one file at a time and publishes this manifest last.
